# Fable Optical Illusion Museum — 実装計画書

[PLAN.md](PLAN.md) に基づく実装計画。

## 1. 概要

ブラウザ上で動作する 3D ミュージアム。来館者(プレイヤー)は館内を自由に移動し、
Optical Illusion(錯視)をテーマにした展示を鑑賞する。
各展示には「見え方のヒント」があり、初期状態では非表示。
ボタンを押すと、その展示がどのような見え方をするのかの説明が表示される。

### ゴール

- デスクトップブラウザで快適に動作する 3D ミュージアムシーン
- 錯視展示を 5〜8 点設置(3D 空間ならではの錯視+額装された 2D 錯視)
- 展示ごとのヒント UI(非表示 → ボタンで説明を開閉)

### 非ゴール(初期リリースでは対象外)

- マルチプレイヤー / オンライン要素
- モバイル・タッチ操作の本格対応(動作はするが最適化しない)
- VR / WebXR 対応
- バックエンド・サーバーサイド処理(完全に静的サイトとして配信)

## 2. 技術スタック

| 領域 | 選定 | 理由 |
|---|---|---|
| 3D レンダリング | Three.js | ブラウザ 3D の事実上の標準。資料・事例が豊富 |
| 言語 | TypeScript | シーングラフ・展示データの型安全性 |
| ビルド | Vite | 高速な開発サーバー、静的ビルドが容易 |
| UI(ヒント表示等) | HTML/CSS オーバーレイ | 3D 内 UI より実装が単純で可読性が高い |
| 状態管理 | 素の TypeScript(イベントベース) | 規模的にフレームワーク不要 |
| テスト | Vitest | 展示データ・ロジックの単体テスト |
| フォーマッタ / リント | Prettier + ESLint | 標準構成 |

React は採用しない。UI はヒントパネルと操作説明程度で、オーバーレイ DOM を直接操作する方が依存が少なく単純なため。

## 3. コア体験の設計

### 3.1 移動・操作

- 一人称視点(PointerLockControls)
  - WASD / 矢印キーで移動、マウスで視点操作
  - クリックでポインターロック開始、Esc で解除
- 移動は床面上のみ(重力・ジャンプなし)。壁・展示への簡易コリジョン(AABB もしくは円柱判定)
- 錯視は「特定の視点から見る」ことが本質のため、**ビュースポット**(床のマーカー)を各展示前に設置し、近づくと視点誘導(位置スナップは任意押下)できるようにする

### 3.2 展示とインタラクション

各展示は共通のインターフェースを持つ:

```ts
interface Exhibit {
  id: string;
  title: string;            // 展示名(プレート表示)
  hint: string;             // 見え方の説明(初期非表示)
  root: THREE.Group;        // 3D オブジェクト
  viewSpot?: ViewSpot;      // 錯視が成立する推奨視点
  update?(dt: number): void; // アニメーションが必要な展示用
}
```

- プレイヤーが展示の近接範囲に入ると、画面下部に展示名と「ヒントを見る」ボタンを表示
- ボタン押下(またはキー `H`)でヒントパネルを開閉
- ヒントパネルは HTML オーバーレイ。説明テキスト+必要に応じて図解画像

### 3.3 展示ラインナップ(初期 6 点)

3D 空間だからこそ成立する錯視を中心に選定する。

| # | 展示 | 種類 | 実装のポイント |
|---|---|---|---|
| 1 | ペンローズの三角形 | 視点依存の不可能図形 | 分断されたパーツが特定視点でのみ繋がって見える。ビュースポット必須 |
| 2 | エイムズの部屋 | 強制遠近法 | 歪んだ部屋を覗き窓から見ると、左右の人形の大きさが激変して見える |
| 3 | ペンローズの階段 | 視点依存の不可能図形 | 無限に上り続けるように見える階段。ビュースポット必須 |
| 4 | ホロウフェイス(凹面の顔) | 奥行き反転 | 凹んだ顔の型が、動きながら見ると顔がこちらを追ってくるように見える |
| 5 | アナモルフォーシス | 歪像画 | 床・壁に歪んで描かれた絵が、特定視点で正しい像に見える |
| 6 | 2D 錯視ギャラリー | 額装絵画(3〜4 枚) | チェッカーシャドー錯視、ミュラー・リヤー錯視、カニッツァの三角形など。テクスチャは Canvas でプロシージャル生成 |

拡張候補(v2 以降): 回転蛇錯視(アニメーションテクスチャ)、無限回廊(ポータル風レンダリング)、色の恒常性の部屋(照明切替)。

### 3.4 ミュージアム空間

- ワンフロア構成。エントランスホール+展示室 2〜3 室を廊下で接続
- ジオメトリは Three.js プリミティブ(Box/Plane)の組み合わせで構築し、外部 3D モデルへの依存を避ける
- 照明: 環境光+各展示へのスポットライト。錯視の成立に影の制御が重要な展示(チェッカーシャドー等)はライトを個別調整
- 雰囲気: 落ち着いた美術館調(暗めの壁、スポットライト強調)

## 4. アーキテクチャ

```
src/
├── main.ts                 # エントリポイント、ループ開始
├── core/
│   ├── App.ts              # renderer / scene / camera / resize / loop
│   ├── PlayerController.ts # PointerLock + 移動 + コリジョン
│   └── InteractionManager.ts # 近接判定、アクティブ展示の決定
├── museum/
│   ├── Building.ts         # 床・壁・天井・照明の構築
│   └── layout.ts           # 部屋・展示配置の定義データ
├── exhibits/
│   ├── Exhibit.ts          # 共通インターフェース・基底クラス
│   ├── PenroseTriangle.ts
│   ├── AmesRoom.ts
│   ├── PenroseStairs.ts
│   ├── HollowFace.ts
│   ├── Anamorphosis.ts
│   └── gallery2d/
│       ├── Gallery2D.ts    # 額装絵画の設置
│       └── textures.ts     # Canvas による錯視テクスチャ生成
├── ui/
│   ├── Hud.ts              # 操作説明、クロスヘア
│   └── HintPanel.ts        # 展示名表示+ヒスト開閉ボタン+説明パネル
└── styles/
    └── main.css
```

### 設計方針

- **展示のプラグイン化**: 各展示は `Exhibit` を実装した独立モジュール。`layout.ts` に登録するだけで館内に追加される。展示の追加・削除が他に影響しない
- **UI と 3D の分離**: 3D 側は「アクティブな展示が変わった」イベントを発火するだけ。UI(HintPanel)はそれを購読して DOM を更新する
- **外部アセット最小化**: ジオメトリはコード生成、2D 錯視テクスチャは Canvas 生成。ホロウフェイスの顔メッシュのみ外部 glTF が必要になる可能性あり(または球・楕円体の合成で簡易表現)

## 5. 実装フェーズ

### Phase 1: 基盤(歩ける空の館)

- Vite + TypeScript + Three.js プロジェクトセットアップ(ESLint / Prettier / Vitest 含む)
- `App.ts`: レンダラー・シーン・カメラ・リサイズ・requestAnimationFrame ループ
- `PlayerController.ts`: PointerLock 移動とコリジョン
- `Building.ts`: ワンルームの仮空間(床・壁・照明)
- HUD: 操作説明とクロスヘア

**完了条件**: ブラウザで館内を歩き回れる。60fps で安定動作。

### Phase 2: 展示システム+最初の展示

- `Exhibit` インターフェース、`InteractionManager`(近接判定)
- `HintPanel`: 展示名表示、「ヒントを見る」ボタン、説明の開閉
- 最初の展示として **2D 錯視ギャラリー**(実装が最も単純)を設置
- ビュースポットの仕組み(床マーカー+視点誘導)

**完了条件**: 展示に近づくと UI が出て、ボタンでヒントの表示/非表示が切り替わる。

### Phase 3: 3D 錯視展示の実装

優先順に 1 点ずつ追加(各展示が独立しているため順次リリース可能):

1. ペンローズの三角形(ビュースポットの仕組みの実証になる)
2. アナモルフォーシス
3. ペンローズの階段
4. エイムズの部屋(覗き窓の視点固定が必要でやや複雑)
5. ホロウフェイス(メッシュ調達 or 簡易生成の判断が必要)

**完了条件**: 各展示のビュースポットから錯視が成立して見える。

### Phase 4: 館内レイアウト・演出仕上げ

- 展示室の本レイアウト(エントランス+展示室、動線設計)
- 照明・マテリアルの調整、展示プレート(タイトル表示)の 3D 配置
- パフォーマンス調整(ライト数の制限、シャドウマップ解像度)
- ロード画面・タイトル画面

### Phase 5: 品質・公開

- 展示データの単体テスト、主要ブラウザ(Chrome / Firefox / Safari)動作確認
- 静的ホスティングへのデプロイ(GitHub Pages または Cloudflare Pages)

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 視点依存錯視が「成立して見えない」 | 体験の核が崩れる | ビュースポットで視点をスナップ可能にする。Phase 3 の最初にペンローズの三角形で仕組みを検証 |
| エイムズの部屋の幾何計算が複雑 | 工数超過 | 覗き窓からの視点を完全固定にして簡略化。優先度を下げ Phase 3 後半に配置 |
| ホロウフェイス用の顔メッシュ調達 | 品質低下 | CC0 の glTF を探す。なければ楕円体合成の簡易版で代替し、v2 で差し替え |
| 低スペック環境でのフレームレート低下 | 体験悪化 | ライト・シャドウを絞る、ピクセル比上限設定、展示の距離カリング |
| Safari の PointerLock 挙動差異 | 操作不能 | Phase 1 の時点で Safari 動作確認を行う |
